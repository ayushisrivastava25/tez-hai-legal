## Enable GitHub Pages once

Open this repository's Settings → Pages. Choose **Deploy from a branch**, select **main** and **/(root)**, then Save. Wait for the Pages deployment to finish. These files are already built; no npm installation, custom Actions workflow, secret, or custom domain is needed. The .nojekyll file disables Jekyll processing.

[GitHub Pages setup documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Current publication status

**Preview, updated 23 October 2026.** The Privacy Policy and Terms have not yet been approved as the final public-release text. They visibly retain the preview notice and request that search engines not index them. This is not access control: this repository and its pages are public.

Before using these as final store policies:

- Choose the effective date: when the reviewed policies begin to apply. It need not match repository creation or store-account enrollment.
- Confirm retention for provider logs/backups, historical analytics and support correspondence. The agreed account-deletion flow blocks access immediately and schedules active account data for erasure after 30 days; it does not automatically erase every provider backup or external copy.
- Review child-account behavior and the intended launch countries. The 13–17 guardian declaration is not verified parental consent. Check that the public disclosures match the actual restrictions, including manual native sharing, which currently has no age gate.
- Confirm publisher/contact details and approve the final wording. Then update both these pages and the app's offline Privacy/Terms copies together.

This is an information site, without playable game code, login, tracking scripts, analytics SDKs or forms. Support and deletion links open an email draft; emailing a deletion request does not itself immediately erase an account. GitHub may process hosting/security request data under its own policies.
